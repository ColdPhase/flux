# Review a rendered Flux view

Use [the design evaluation guidance](../../../docs/design/README.md). Request
the actual screenshot, neutral persona/job brief, viewport/zoom, accepted
constraints and reference images. Work in a fresh reviewer context without
implementation code, revision history or the author's rationale. If those
conditions cannot be met, identify the result as self-assessment or limited review.

- Assess what attracts attention, whether scale suits the user job, which action
  is discoverable, and how much of the viewport supports useful work.
- Give at most three material problems. For each: location, visible symptom,
  consequence for the user, and direction of improvement.
- Identify useful elements to preserve. Distinguish observable hierarchy or
  readability problems from your stylistic preference; references are not templates.
- Report missing states and questions for live testing. An image cannot verify
  keyboard behavior, data correctness, responsive transitions, or WCAG compliance.
- Return evidence tied to the screenshot/revision. Do not edit implementation or
  approve a whole functional task on the strength of its appearance.
