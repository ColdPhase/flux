| F-030 | **A workspace can be encrypted at rest, and is then always without AI** ([contract](encrypted-workspaces.md)): chosen only at creation, irreversible. Server-side, not E2EE: a per-workspace 32-byte data key (DEK) seals every content column (AES-256-GCM with a per-row HKDF key, random 96-bit nonce, length-prefixed AAD = workspace, field, row identity and key version), including idempotency responses of every command (mandatory command scope), file bytes and stored digests (sealed SHA-256), and search keeps only content-free placeholder rows on disk with an in-RAM index per API process. Every key version's DEK is sealed to an X25519 key pair per holder, whose private key is wrapped per owner/admin unlock password or by a one-time recovery code; holder rows carry a DEK-derived MAC, the public key is bound into the private key's AAD, and every opened DEK needs the holder's own password-derived confirmation or a commitment from the previous version, so a database writer cannot plant a key or forge a wrap (`409 ENCRYPTION_TAMPERED`) (Argon2id m=64 MiB, t=3, p=4, RFC 9106 second option; a generated six-word passphrase by default, own passwords at least 20 characters and a zxcvbn-ts estimate of at least 10^17 guesses; one limiter and semaphore for every route that checks a secret; a new holder's first password needs a holder's grant or the recovery code). After a restart the workspace is locked (`423 WORKSPACE_LOCKED`, fail closed, waiting jobs parked) until an owner or admin unlocks it; the DEK then reaches every API and worker process sealed under the boot key of a single RAM-only `keyring` process on one host (constant-time token, no cross-host use without TLS), stored in `workspace_unlocks`; no key is opened where swap could write it to disk (cgroup or `/proc/swaps` check, or an operator acknowledgement), so PostgreSQL never sees a plaintext key and a keyring or stack restart locks everything.
