## Adopted bounded contract

**[D] Owner switches:** use the normally authenticated connection-owner session, without password replay, ten-minute/auth_time thresholds or a secondary SSO challenge. Persist/version controls for actual Read/Suggest/Execute capabilities and selected native projects. Effective authority is current owner rights ∩ actual agent project grants ∩ original connection/OAuth consent ∩ selected places ∩ live policy; effects additionally need the existing bounded grant/runtime/source conditions. The current [S6 contract](../mcp-identity.md#s6--owner-mcp-capability-switches) preserves all-disabled management, stale-save/refusal states, no hidden grant/admin/private/DM/decision-acceptance/paid-invocation powers, and exact-head API/browser evidence.

**[D] Live Off/On:** Off applies after commit at the next protected projection/read/effect/delivery or receipt replay check, with serialization and held-race proof. Earlier committed history/effects and bytes already handed to transport cannot be retracted; unrelated local CLI work is not promised to stop. On restores only a restriction permitted by still-valid consent, rights and real grants, never revoked/expired/used-up authority. Preserve original consent/receipt identities through a restrictive versioned policy overlay or an independently accepted equivalent.

**[S] OAuth scope ceiling remains:** [RFC 6749 §6](https://www.rfc-editor.org/rfc/rfc6749#section-6) prohibits refresh scope beyond the original grant. [MCP authorization 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization) describes scope-related refusal followed by new authorization. Scope reconsent is ordinary explicit authorization for a larger envelope, not proof of recent human authentication and not a ten-minute password gate. Refresh must not silently broaden the old scope/place consent.

**[D] Exclusive modes and migration:** password-only without active SSO, or SSO-only through the sole active IdP. Refuse ordinary Flux password sign-in/signup/reset and password-only authority under SSO; new SSO accounts need no Flux password. Before cutover, the authenticated existing account completes a verified prepared-provider callback bound to the same account/session/intent, preserving Flux ID/data/roles/memberships/applicable grants. Duplicate/substituted identities and email auto-linking are refused. Audited host recovery/re-key handles stranded accounts; it is not ordinary mixed login or a second password challenge. Current [S5a/S5b](../mcp-identity.md#s5b--password-mode-safe-migration-and-provider-claim-adapters) retain collision/verification/offboarding and actual selected-provider compatibility gates.

## Inference, limits and pending evidence

**[I] Implementation choice:** current immutable consent fields are not mutable permission switches. A versioned restrictive policy overlay can preserve them while composing with live projection/effect/replay checks; an alternative requires independent assessment. UI labels alone, caches or signed but old tokens do not enforce new settings. Fully disabled connections must remain manageable. Read-off/Actions-on cannot claim independence from the current bootstrap path.

**[I] Assurance boundary:** a valid ordinary session and IdP standing are not proof of recent human authentication. The founder has chosen the ordinary owner-control UX instead of that additional safeguard. This is not a claim that the removed guard was already implemented or that all compromised-session risks disappear. Existing session/origin/CSRF/owner/project/OAuth/grant checks remain required; no new assurance is invented.

**Pending:** Docker API/browser positive and negative controls for owner vs other-owner/admin/agent, reload/persistence, failed/stale saves, old-token Off/On and refresh ceilings, held authorization/effect/delivery races, replay/revocation/expiry and all-disabled/prerequisite states; exclusive mode, verified pre-cutover migration, identity collisions, data preservation and audited recovery. Real selected-provider compatibility stays unverified; no mock establishes it. F-026 #343/#347/#350 use one permissions surface. Source/contract acceptance does not complete any of these runtime gates.
