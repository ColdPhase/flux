## Evidence rule

`gap` means no bounded application contract currently covers the behavior. `planned` means an assigned issue contains a candidate or accepted contract for at least part of the behavior; it **does not** mean code exists or all work in the row is scheduled. `implemented` requires merged behavior, a resolving issue and reproducible checks at a named commit. `verified` requires criterion-specific independent evidence at the tested commit. A planning PR, merged research, screenshot, passing harness check or label cannot raise an application row to `implemented` or `verified`.

At this revision protected `main` includes [#28 / PR #34](https://github.com/ColdPhase/flux/pull/34) and the merged [#29 event/policy slice in PR #47](https://github.com/ColdPhase/flux/pull/47), alongside other foundation work. It does not yet deliver a complete user journey, device test or release artifact. Therefore no **product area or pillar** row is implemented or verified. [#36](https://github.com/ColdPhase/flux/issues/36) has an unmerged two-person project capture and conversation candidate with Docker evidence at the cited head; its final integrated UI review is pending. [#20](https://github.com/ColdPhase/flux/issues/20) has an accepted mobile contract without merged device behavior. [#14 / PR #24](https://github.com/ColdPhase/flux/pull/24) is an accepted **journey document**, and [#13 / PR #25](https://github.com/ColdPhase/flux/pull/25) is an accepted **architecture decision**; neither proves application behavior. ## Update protocol

Every feature PR names the rows it advances and edits this ledger before independent review. Include the accepted issue contract, resolving PR, tested commit, exact behavior/check, and remaining failure cases in that PR. Keep the row `planned` if a PR is unmerged; move to `implemented` only after merge with reproducible checks, and to `verified` only after an independent criterion-specific report at the current candidate. A new code head or changed contract needs affected checks again. The #16 owner reconciles this initial ledger with accepted O-decisions before its final review. The two agents audit all rows and MOB evidence at one protected-base candidate before the explicit final release workflow and [full-product acceptance](../agents/github-protocol.md#full-product-acceptance).
