## Running the automated rows

```sh
scripts/release/acceptance.sh --list                 # steps, commands and matrix rows
scripts/release/acceptance.sh <candidate-sha>        # every step, serially; evidence in
                                                     #   .worktrees/acceptance-<sha12>-evidence/
scripts/release/acceptance.sh --resume <sha>         # rerun only what did not pass
scripts/release/acceptance.sh --only ui-webkit <sha> # one step
```

The runner checks out the candidate as a clean detached worktree (`.worktrees/acceptance-<sha12>`),
runs the **candidate's own** scripts there one at a time (concurrent Docker suites give false
failures), uses ports from `FLUX_ACCEPTANCE_PORT_BASE` (default 34000), blanks the `FLUX_VAPID_*`
variables of a dev `docker/.env`, and writes `<step>.log`, per-step evidence folders,
`status.tsv`, `environment.txt` and `SUMMARY.md`. It never pushes, freezes `main`, posts on
GitHub or dispatches a release workflow. `--dispatch-checks` only dispatches the two fast
required-check workflows when `origin/main` already equals the candidate. Three steps download
the pinned real CLIs (no account): skip them with `FLUX_ACCEPTANCE_OFFLINE=1`, which leaves
their rows unverified. Expect several hours; the two UI suites and the release dry run are the
longest.

Commit only a short report (SHA, step results, failures); keep raw logs and screenshots out of
the tree ([evidence size](../evaluation.md#evidence-size)).
