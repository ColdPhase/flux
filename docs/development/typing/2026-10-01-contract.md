## User outcome and scope

A person reading an existing shared conversation/DM/task sees when another
currently authorized human is writing there. Names identify actual people;
activity is never inferred from unread, agent heartbeats or model thinking.
Keep native sources, participant audiences, drafts, focus and reading anchors.
Task/Agents surfaces use the same native task and canonical discussion identity,
not another chat. Before the first project conversation exists, typing must not
create a durable conversation/root merely to display presence.

Agent execution/review activity and navigation/arrival/drop motion retain their
separate existing #155 criteria. Human typing grants no external connection,
model use, work/result publication or invitation authority. Future agent activity
must derive from authenticated actual execution, not this human typing channel.

## Transport and domain boundaries

Use a separate authenticated same-origin cookie WebSocket `/api/v1/typing`,
registered through the existing Fastify websocket dependency. It has no durable
cursor/replay and cannot change the ordinary event stream protocol or sequence.
Wire contracts belong in `contracts`; normalization/lifecycle/access ports in
`core/src/typing`; current policy/identity/socket composition in `server/src/typing`;
PostgreSQL notification transport/adapters in `db`; browser hook/notice in `web`.
No new core adapter imports, mutable module singleton or host service.

Closed client messages: watch one `{kind: conversation|dm|task, id: UUID}`;
active true/false for that watched context; leave. Reject extra properties,
malformed values and frames over1024 bytes without echoing their contents.
The client cannot provide author/session/connection/name/time/TTL or text.
Server assigns a fresh connection identity and monotonic update sequence.
Only currently authenticated humans may publish. A viewer may watch permitted
native objects but never publish under read access.

Core ports authorize the actual native resource via the existing central policy:
project conversations under their live project role; DM under current participant
read/write rules; native tasks via current work access. DM publication also
requires the same current open-conversation/counterpart condition as native
`send`; `evaluateDm(dm.write)` alone only proves participation and is insufficient. Missing/read-denied/wrong
scope targets are content-free unavailable. Sender current session/write authority
is rechecked before pulse; actual receiver session/read and sender current write
are rechecked before every visible snapshot. Names come from current authorized
native identity metadata, never caller text. No permission/payer impersonation.

Canonical task/conversation aliasing must use #154's actual root mapping and
current policy. Do not guess its table/namespace or create a root on a read.
If that composition is not yet present on main, preserve an explicit integration
gap and finish it against the accepted #154 primitive before full #155 acceptance.
Task/Agents callers use native task identity; duplicate tabs/connections of one
human show one person. Existing conversation IDs never become a new backlog.

## Nondurable distribution and lifecycle

Reuse PostgreSQL LISTEN/NOTIFY on a distinct constant channel; publish only
strict internal metadata after current authorization, with no insert/update of
messages/events/audience/outbox/notifications/queue/domain rows. Each API instance
has an injected bounded in-memory lifecycle store. NOTIFY is a wake/activity
transport, not history; reconnect/restart/notification-listener uncertainty clears
local state and invalidates in-flight listener work by generation. Handle both
connection error and clean unexpected end; successful initial LISTEN/reconnect
starts empty. No import/restore/replay resurrects a pulse.
Use the database clock for broker expiry and receiver expiry checks: wall-clock
skew between API hosts cannot extend a lease or resurrect a stopped participant.
Record actual expiry-query behavior and latency. Monotonic local clocks drive
throttles/debounce only; no browser clock or caller TTL is trusted. If transport is unavailable,
show activity unavailable/unknown instead of presenting cached presence as current.

Broker metadata contains server-assigned connection/session/actor/context,
sequence and server expiry only; public snapshots exclude session/internal IDs.
Cookies, bearer tokens, email, draft text and client-supplied identity never enter
the broker. An adapter reads the exact current native auth-session row, bound to
its human actor and expiry, before accepting a remote sender into any visible
snapshot/heartbeat. Local cookie resolution alone cannot certify another API
instance’s sender. Missing/revoked/expired sender sessions remove activity.
Late async results check connection/scope generation; older sequences cannot
reactivate after stop/scope change. Retain a bounded tombstone until older pulses
have expired. Each tombstone lives through the maximum expiry of the older
sequence it suppresses; a stop receives its own database-clock expiry at least
as late as every earlier active pulse on that connection. Drop already-expired
notifications. Also cap receiver lifetime at5000ms of monotonic time from receipt
so database wall-clock adjustment cannot extend retained presence indefinitely.
Never evict a necessary tombstone then accept an older sequence: saturation
invalidates that whole watched generation until its expiry window drains. Serialize publication per
connection; on send, blur, hide, navigation, scope change and disconnect clear it.
Every watch/stop/leave/disconnect and listener-availability transition invalidates
the relevant generation synchronously. Recheck generation, expiry and the socket
state after asynchronous policy/session work and immediately before publication
or sending. A heartbeat does not authorize a later queued send indefinitely.
Only already authorized, still-current snapshots may reach the socket; a
concurrent revocation after the last check has the stated bounded withdrawal
latency, not an impossible instantaneous network guarantee.
Unclean disconnects expire within the stated bound; a lost network cannot promise
instant remote detection. Viewers losing scope and senders losing session/write
are withdrawn on the next checked update or heartbeat, without native events.

Client debounce180ms, active refresh at most once/1500ms; server at most one
accepted active pulse/1000ms, stop always immediate. Expiry5000ms, authorization/
expiry heartbeat1000ms. No per-keystroke read model work or repeated announcements.
Bound one watched scope/socket, eight sockets/human/API and128 sockets/context;
record actual capacity behavior without exposing foreign room names/counts.
Additionally cap each API at512 sockets and128 watched contexts; retain remote
activity only for locally watched contexts, at most512 connection entries/context
and4096 entries/API (including stop tombstones). Reject new admission on local
capacity, never silently evict current authorized participants to claim complete
presence. On remote-store saturation clear the affected context and report
activity unavailable until its expiry window has drained; names/counts from an
incomplete store are never shown as a complete current snapshot.

Public snapshots carry only the watched canonical context, availability and at
most128 deduplicated authorized human IDs/names. Normalize names to128 Unicode
code points without controls; never include emails or synthetic former-user
names. Cap serialized public frames at64KiB; saturation reports unavailable,
not a partial set presented as complete.

Bound all client commands, including watch/stop/leave, to4 frames/second with
burst8/socket, separate from the active-pulse rate. Normal stop is never delayed
by active throttling; flooding closes the socket and invalidates pending work.
Keep at most one running authorization and four pending commands/socket; watch/
leave/stop cancel obsolete active work. Broker processing has one running and
one coalesced latest update per retained connection, never an unbounded promise
chain. Outgoing snapshots have one running and one coalesced latest pending
snapshot/socket; close when its transport buffer exceeds64KiB. API-wide bounded
work/capacity counters are part of the stress proof, without private payload logs.
No capacity eviction may retain hidden or stale typing. On shutdown remove state
and stop timers/listeners without touching another Compose project's resources.

UI displays a quiet static notice beside the real composer, preserving its
accessible input and current audience. Readers get a readable notice but no
write invitation. Local draft text never crosses the typing channel. Reduced
motion remains static; hidden/modal-obscured controls stop optional motion.
Expiry refreshes must not repeatedly announce unchanged names. All input/send,
focus, shortcut, source navigation and explicit recap semantics stay unchanged.
