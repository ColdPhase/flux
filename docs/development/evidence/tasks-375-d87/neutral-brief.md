# Neutral visual brief — PR #375 phone Tasks

Source revision: `d87fde2df4cbddafc8fb6c4771d5d9fda9eab8a2`.

Compare the supplied current-revision screenshots with the relevant F-026 Prostota references. Assess visual hierarchy, density, legibility, and the separation of the task feedback toast, floating Create button and bottom dock. Do not infer interaction or accessibility from the images. The phone reference is `docs/design/final/screens/phone-tasks.webp`; `phone-taskfull.webp` shows task detail context.

The test fixture is Community garden sensors with six tasks: three Open, one Blocked, one In progress and one Done. Ownership is Ada (three), Jonas (one), Claude Code (one) and unowned (one). The list is shown with All selected. On phone, the Tasks toolbar is absent and the view menu is in the project title.

Frames use 100% browser zoom and device scale factor 3. The `346-tasks-phone-390-*` images are CSS 390×844, captured in the initial All-list state. The `346-tasks-phone-320-*` images are CSS 320×568, captured after a state change was undone and its confirmation dismissed; task states are back to the initial fixture. The `375-feedback-success-{320,390}-*` images show the confirmed In progress state with an Undo toast visible. The `375-feedback-error-{320,390}-*` images show the offline error toast. Each suffix is either `light` or `dark`.

All supplied images were generated by the `TasksFinalJourney` tests in the Docker UI run for the source revision above; no product-source overlay was used. Their names and dimensions encode the viewport/theme/state. The 320×568 images represent a narrow, short phone viewport; 390×844 is the reference phone viewport.
