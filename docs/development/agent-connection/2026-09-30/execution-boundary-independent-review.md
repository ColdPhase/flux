Accept the caller-owned, already-open transaction boundary and one canonical `(connection_id, client_command_id)` ledger. The normalized fingerprint includes verified binding/runtime/session/grant, exact operation/class/project/audience/object/source conditions and payload. Current authority precedes command/slot/task/unit locks; fresh database wall time follows relevant waits and precedes final completion. New effects debit and store one receipt atomically with domain/coordination/outgoing writes; matching last-use replay checks current authority without requiring another unused use or debit. All audiences prepare before the final stream event batch. No separate receipt transaction or second content store is introduced.

Implementation conditions: configured scope/context is an internal trusted handle, never a caller-serialized authority object; complete must verify it belongs to the same transaction/binding/command. Produced postconditions come from canonical domain rows, not MCP-supplied outcome metadata. Conditions are typed and operation-specific, with known immutable IDs/version/generation/session fences; unknown kinds fail closed. Replays return the original result and original lease/session/generation, never renew or acquire a claim. The original effect advancing its own version is compatible; an external intervening edit/deletion is visibly stale under the recorded post-state rule.

Keep historical receipt observation separate from authorization to continue work: the pure #153 core test returns an original claim after that historical lease expires, with no renewed authority. Runtime/grant expiry/revocation/visibility still deny access. For claim replay, do not accidentally demand a newly live lease to return the unchanged historical effect; actual resumed effects require current live fences. Coordinate the exact #153 operation-specific postcondition with its owner before enabling claim writes.

Native task dependency/plan-intent writes require the separately accepted canonical field extension and cycle/version/uniqueness rules.
