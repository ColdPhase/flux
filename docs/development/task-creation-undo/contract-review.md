## Accepted policy decisions

**Exact origin and actor authority.** Accept native trusted agent creation and the committed proactive-comparison proposal-use binding as the two AI-origin paths. The latter creates work as its accepting human today; that human remains the creator. An agent modification of human-created work, an AI label, a client flag, a source citation or an event-text guess does not establish AI creation. Origin remains immutable even if the connection is later revoked.

Accept the proposed human policy: current project write plus actual human creator, current human assignee, or current human owner of the genuine creator-agent. An unrelated contributor or project administrator does not qualify merely through broad write/manage rights; the owner of a different assigned agent does not become a human assignee. The producer of a suggestion gains no task authority unless independently qualifying under those rules. Initial human assignment can qualify; a later assignment change already makes the task used and therefore ineligible.

Accept the separate exact `work.creation.revert` agent operation, classes execute/plan, restricted to that same genuine agent's own native-created task. It must use the existing current connection, binding, runtime, audience, scope, grant, quota and receipt composition. `work.update`, work.create, reviewer grants, another connection's grant, same-human-owner identity, and an old receipt supply no new reversion authority. F-016 CO-1 explicitly reserves new actions and F-019 separates the owner, agent identity and invocation authority. Human reversion invokes no personal AI: revoking the old creator connection does not itself remove a qualifying human's current project-write/creator/assignee/creator-agent-owner authority. Revocation tests must distinguish that from an agent command, which must fail under a revoked connection/runtime/grant.

**Feature-start baseline and monotonic use.** Accept a trusted creation-time baseline only for new creations produced while the complete actual writer fence is in force. Older rows without complete persisted-use history are `eligibility_unknown`, even if they have version 1, known agent authorship or no current related rows. This refusal is justified by the actual destructive replacement of dependency and mention links; reconstruction cannot prove never-used history. No historical notices, authors or origins may be inferred.

The new task's own creation notice, initial owner/source/related links, plan correlation and originating proposal-use binding are creation provenance. They are not subsequent use of that newly produced task. Creating such a link to an already existing task does use that existing task, which must enter the complete affected-task fence. A later saved proposal/reference, private helper execution, handoff/claim/checkpoint, dependency, doc mention, result, decision, live presentation/session, PR binding, contribution or task mutation permanently prevents Undo even after the related row is removed. Creation with a dependency already fails the plan's no-dependency predicate. Reads, previews, drafts and uncommitted typing remain side-effect free. Failed or rolled-back attempts set no latch.

**Retained history and retries.** Accept a separate lifecycle marker rather than deletion or a sixth board status. Original task/notice/source/proposal/plan/receipt identities remain; the append-only reversion notice records the actual reverter and time. Existing links open current-authorized read-only reverted Details. A repeated matching Undo command observes its durable reversion receipt after current reauthorization; it must not rerun the original never-used predicate against its own already-reverted result. Changed command material conflicts. Creation retries can return a truthful historical projection or a typed terminal/stale conflict; they cannot return the old active success, create a replacement, or free a used proposal for reuse.

**Writer and notification semantics.** Accept sorted complete task locking, atomic latch/reversion, one caller-owned transaction and a final event batch. The required writer inventory must include both endpoints of task-related links, current and replacement dependency/mention targets, generic replies through the bound conversation, and the live/PR/helper/proactive adapters as well as core work commands. Current lock orders require deliberate integration: material/graph and provider/binding fences precede tasks; decision acceptance currently holds a decision before tasks, so implementing the shared fence must avoid introducing the inverse task-to-decision order. An isolated domain fixture cannot certify all adapters.

Accept suppression of delayed assignment generation and queued dispatch after lifecycle recheck, with previously delivered notifications preserved as history. An already in-progress provider send cannot be recalled. That boundary does not permit a fresh queued assignment after a committed reversion. Existing historical links and current ACLs remain required at every surface.
