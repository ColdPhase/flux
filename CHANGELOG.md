# Changelog

All notable changes to Flux are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Flux uses
[Semantic Versioning](https://semver.org/spec/v2.0.0.html) for its releases.

**Keeping it current.** A pull request that changes what people or operators see adds
one file under [changes/](changes/README.md) with its PR number, instead of editing this
file, so that parallel pull requests do not conflict here. This covers features, changed
behaviour, fixes, removals, security fixes and new operator steps. Internal refactors,
tests and agent-process changes need no entry. At release time,
`python3 scripts/changelog.py release <version> <date>` moves the pending entries under
that version; the older entries under 0.1.0 were written before that rule.

## [Unreleased]

## [0.1.0] - 2026-11-01

The first release of Flux. It is published for `linux/amd64`; `linux/arm64` follows in 0.1.1. There is no earlier
version, so there is nothing to upgrade from. The [release notes](docs/product/release-notes-v0.1.0.md) say what
Flux is, how to install it and what is not in this version. Everything below was built since the repository was
created on 2026-09-26.

### Added

#### Run and operate Flux

- Operators can offer owners their own Claude Code inside Flux (off by default, `FLUX_AGENT_RUNTIME`): a fixed pool of isolated runtime slots with no Docker socket, `./flux runtime status|release|purge`, and slot volumes kept out of backups ([#303](https://github.com/ColdPhase/flux/pull/303)).
- One Docker Compose application with the API, a separate worker, PostgreSQL and a
  durable job queue. Migrations are reviewed SQL with health checks ([#34](https://github.com/ColdPhase/flux/pull/34)).
- `./flux up`, `./flux demo` and `./flux dev` start, seed and develop Flux with only
  Docker installed ([#102](https://github.com/ColdPhase/flux/pull/102)).
- Backup, restore, project export and upgrade through `./flux backup`, `restore`,
  `export` and `upgrade` ([#127](https://github.com/ColdPhase/flux/pull/127)).
- Operator Compose files and versioned installation assets for released images
  ([#159](https://github.com/ColdPhase/flux/pull/159)), plus a gated, explicitly
  triggered OCI release workflow ([#104](https://github.com/ColdPhase/flux/pull/104)).
- An exact migration-ledger check at install and startup. A database that does not
  match the image's migrations refuses to start ([#130](https://github.com/ColdPhase/flux/pull/130)).
- Two public extension contracts with a written compatibility promise: MCP tool
  contract 1 and project export format 1. A versioned snapshot test catches a
  breaking change. The [integration guide](docs/integrations/README.md) is for
  integrators and operators ([#260](https://github.com/ColdPhase/flux/pull/260)).
- A tested HTTPS reverse-proxy guide (Caddy) that keeps one public origin for the UI, sign-in, MCP and live updates, and trusts only the measured proxy address ([#366](https://github.com/ColdPhase/flux/pull/366)).
- `FLUX_BACKGROUND_COMPARISONS`, an operator switch that registers the comparison runtime; off by default, with behaviour unchanged ([#212](https://github.com/ColdPhase/flux/pull/212)).
- Live media: a recorded encryption boundary (hop-by-hop, not end-to-end) ([#284](https://github.com/ColdPhase/flux/pull/284)).
- A documentation site at <https://coldphase.github.io/flux/>, generated from the repository's user-facing docs, and a README with the Kreska header, badges and highlights ([#740](https://github.com/ColdPhase/flux/pull/740)).
- A self-hosting section in the documentation: requirements, a production installation on your own domain, tested Caddy, nginx and Traefik examples, an operator architecture diagram, operating encrypted spaces, health, monitoring and logs, capacity, hardening, troubleshooting and FAQ, and administration in the app, with a configuration reference generated from the code that the repository check keeps in step ([#780](https://github.com/ColdPhase/flux/issues/780)).
- `./flux up` asks once, on its first interactive run, whether people on this Flux may sign in with their own ChatGPT and Claude subscriptions, and the new `./flux ai on` asks the same on an existing instance. Enter means yes (Codex); Claude Code needs a typed `y` to Anthropic's Commercial Terms, which writes today's date as your statement. Hosts whose Docker engine cannot run the agent runtime (no Yama `ptrace_scope`, no internal networks, no limits, Docker Desktop) are not asked and get one line saying why; without a terminal nothing is asked or written ([#494](https://github.com/ColdPhase/flux/pull/494)).

#### Encrypted workspaces

- Operators: a new `keyring` service (encrypted workspaces, F-030, S1) runs on an internal network with `api` and `worker`; `./flux up` generates its `FLUX_KEYRING_TOKEN`. `api`, `worker` and `keyring` now have memory limits with swap limited to the same value (`FLUX_API_MEMORY` 2g, `FLUX_WORKER_MEMORY` 1g, `FLUX_KEYRING_MEMORY` 128m) and core dumps off. ([#655](https://github.com/ColdPhase/flux/issues/655)).
- People can make an encrypted space from Home → Details → People → New space: a generated six-word unlock password or their own, a recovery code shown once to print, and no AI in it, for good. An encrypted space that waits to be unlocked shows as one row ("Waiting to be unlocked") and as a locked panel at every address inside it; owners and admins unlock it there, and open tabs follow the lock and unlock without a reload. People → Encryption lets owners and admins change their unlock password, lock the space, let another admin set a first password and make a new recovery code, and says what removing an owner or admin changes ([#655](https://github.com/ColdPhase/flux/issues/655)).
- Encrypted workspaces (F-030, S2b): search and live editing of docs and maps work in an encrypted workspace while it is unlocked. Each API process keeps an in-memory search index of an unlocked workspace (never written to disk, dropped when the workspace locks). `FLUX_SEALED_SEARCH_MAX_BYTES` (default 256 MiB of estimated heap) bounds one workspace's index and `FLUX_SEALED_SEARCH_PROCESS_MAX_BYTES` (default a quarter of the API container's memory, at most 512 MiB) all of them in a process; a workspace that does not fit answers `sealedUnavailable` and idle indexes are evicted to make room. Live Wiki and map updates, snapshots and receipts are stored sealed, and locking a workspace closes its live rooms. ([#655](https://github.com/ColdPhase/flux/issues/655)).

- Settings → People shows each workspace's people and roles in one place, also from the account menu; owners and admins can invite someone who has no account yet with an invite link (F-035) ([#763](https://github.com/ColdPhase/flux/issues/763)).
- Someone who manages two workspaces chooses where a new project goes with "In … ▾" ([#763](https://github.com/ColdPhase/flux/issues/763)).

The person opens the link, signs in or creates an account, and joins with that role. Pending links are listed with Copy and Revoke; a link works once, and Flux sends no email itself. In an encrypted workspace an admin who joins gets an unlock password only from someone who has one ([F-035](https://github.com/ColdPhase/flux/blob/main/docs/development/access-policy.md#invite-links-f-035), [#763](https://github.com/ColdPhase/flux/issues/763)).
