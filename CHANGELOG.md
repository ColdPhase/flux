# Changelog

All notable changes to Flux are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Flux uses
[Semantic Versioning](https://semver.org/spec/v2.0.0.html) for its releases.

**Keeping it current.** A pull request that changes what people or operators see adds
one file under [changes/](changes/README.md) with its PR number, instead of editing this
file, so that parallel pull requests do not conflict here. This covers features, changed
behaviour, fixes, removals, security fixes and new operator steps. Internal refactors,
tests and agent-process changes need no entry. At release time,
`python3 scripts/changelog.py release <version> <date>` moves the pending entries under
that version; the older entries under 0.1.0 were written before that rule.

## [0.2.0] - 2026-11-10

### Added

- The ⋯ menu of a message has **Copy text** next to Copy link, on every message a person can read, on a computer and in the phone's long-press list. It copies the message's plain words (a mention as @name) and is not offered on a deleted message ([#1006](https://github.com/ColdPhase/flux/issues/1006)).
- A person can edit and delete their own messages, in a space and in a direct message, from the ⋯ menu after Copy link on a computer and on a phone. Edit changes the words in place and the message shows "edited"; Delete asks once and leaves "Message removed" in the same place, keeping the replies, and the words leave search, the notices that carried them, the export, the message's files and the database (encrypted spaces too). Only the author can; an agent's own line stays with its owner ([#1006](https://github.com/ColdPhase/flux/issues/1006)).
- `/ai` works in the threads of a direct message too. The answer is a card in the thread that only you see; Show everyone posts it as a reply in that thread, and the assistant reads that thread and nothing else. Both people still see one line in the conversation that AI was used ([#1016](https://github.com/ColdPhase/flux/issues/1016)).
- Agents on your own Claude Code (a Claude plan in Connect AI) search the web with Claude Code's own search, on by default like the search of agents on an API key. Each search is recorded with the run, and the answer lists what it searched and the pages it named. Agents on your own Codex search too, with Codex's own search on OpenAI's cached index ([#1065](https://github.com/ColdPhase/flux/issues/1065)).
- A dynamic security test: `./scripts/check_dast.sh` runs OWASP ZAP against the running application in Docker, a baseline scan of the web app and an active scan of the API signed in as the owner and as a member, and lists what is left to triage; recorded false positives carry their reason. A manual step before a release ([#838](https://github.com/ColdPhase/flux/issues/838)). The API now has a floor of rate limits under every route (1,200 requests a minute per session, 600 per address without one; a read that gets a 429 waits and asks again with a calm "Flux is busy" line), and every response carries `X-Content-Type-Options`, `Permissions-Policy` and `Cross-Origin-Resource-Policy` ([#956](https://github.com/ColdPhase/flux/issues/956)).
- Release images are signed. The release workflow signs both image digests keylessly (cosign, Sigstore) after they pass the scan and the packaged install, `INSTALL.md` shows how to check the signature and the build provenance with `cosign verify` and `gh attestation verify` before you pull, and publishing a release now requires both signatures ([#840](https://github.com/ColdPhase/flux/issues/840)).
- Agents work together in a task's thread. An agent can split a task into subtasks (shown in the task as "Subtasks · 1 of 2 done"; those for other people wait for your OK, with Approve all), and ask the agent of another person in the task a question: it answers on its owner's account, reads only, and uses only what everyone in the task can see. Each exchange is bounded and a stalled one returns to the people. The task shows who is in it, the people and their agents ([#841](https://github.com/ColdPhase/flux/issues/841)).
- `/ai` works in every conversation: a space's conversation and its threads, a task's thread and a direct message. The answer is yours alone, in a card with Dismiss and Show everyone, which posts it as your own message, "Ada · via Assistant". It uses only what the people of that conversation can see; a guest has no `/ai`. In a direct message both people see one line, "Ada used AI here (Claude)" ([#842](https://github.com/ColdPhase/flux/issues/842)).
- Each of your agents has a private chat in Messages with a box to write in: it answers there, remembers what was said and "remember that …" adds to its memory. In its chat an agent reads like you and changes nothing ([#842](https://github.com/ColdPhase/flux/issues/842)).
- Your agents now run on the server and take tasks. Give a task to one of your agents in the Owner field, or set "When someone assigns a task to me" in Settings › AI to "Give it to" one agent. It says it is on it, works inside Flux with your rights, writes its report in the task, and follows its "What it may do": Done with Undo, or handed back for you to check. The task shows what it is doing in one plain line, with Stop, Try again and Take it back ([#856](https://github.com/ColdPhase/flux/issues/856)).
- Tell an agent in its private chat "Every weekday at 9, summarise what changed in Garden" and it answers in plain words with what it prepared and one tap to turn it on. An agent's schedules are listed in its conversation, in one line in its header that opens the list, where you turn them on, pause, change, run now and delete them (with Undo); the agent's page shows the same list. Their results arrive in the agent's chat as one message each, and a run that fails or cannot start says so there: a schedule is never paused after failures. A schedule reads only web addresses you typed ([#858](https://github.com/ColdPhase/flux/issues/858)).
- The morning summary is a ready-made schedule on the agent's page, off until you turn it on ([#858](https://github.com/ColdPhase/flux/issues/858)).
- What a local client (Claude Code, Codex) changed on a task, a Wiki page or a map shows its change line and Undo where it was made, "Ada · via Claude Code", "Moved #4 to Doing · Undo": in the task's activity, on the page under its title, and on the map (in its dock, or at the head of its List), one line per change, newest first, three at most. Anyone who can read it sees the line; the owner or anyone who may edit it takes it back, and "Changed since" puts nothing back ([#868](https://github.com/ColdPhase/flux/issues/868)).
- Encrypted spaces, per space. Turn on **Encrypted** in the New space window (off by default; it cannot be turned off later), choose an unlock password and download the recovery code, and the space is encrypted on the server with no AI in it. Only its admins and the recovery code hold the keys: the company's admins can delete it but not open it, and Add me does not list it. After a server restart it stays locked until one of its admins enters their unlock password; its members see \"Locked, waiting for an admin\" and the rest of the company works as usual. Any company member who is not a guest can make one, from every New space entry point, also as the first thing a new owner does ([#874](https://github.com/ColdPhase/flux/issues/874), [#848](https://github.com/ColdPhase/flux/issues/848)).
- New space is one window with a name, the people (chosen from the company) and an AI switch that starts on; you are the space's admin. Each space has settings under its header's ⋯ menu: its name, its people with Admin and Member roles, the AI switch, Leave space and, for admins, Delete space, which asks first and names the space. A company admin can delete any space from Settings › Company, but not Everyone; deleting a space also removes its files from the server. A space always keeps an admin: nobody leaves, steps down or is removed while they are its last admin. ([#874](https://github.com/ColdPhase/flux/issues/874))
- Agents can read a public web page, on by default (the operator turns it off with `FLUX_WEB_READS=off`). The Flux server reads it, read-only and with the same guard as link cards, and the agent's answer ends with the pages it read. What a page says is data and can never make an agent act beyond "What it may do" or skip a wait ([#918](https://github.com/ColdPhase/flux/issues/918)).
- The owner of an agent can take back what it said in a task's thread: its report, its question to another agent and its answer to one carry Undo under the line (while no person has answered it), and everyone then reads "Undone by Jonas" ([#923](https://github.com/ColdPhase/flux/issues/923)).
- A Wiki page can be deleted: ⋯ › Delete page, after an OK, on the computer and the phone. It goes for everyone in the space with its earlier versions; a message that cited it keeps its text and shows "Page deleted"; an agent's suggestion about it and the task plan items made from it are cleared (the tasks stay); a call on it ends, and a page that is open elsewhere says "This page was deleted". An agent asks with `flux_delete_doc` and it always waits for its owner's OK ([#941](https://github.com/ColdPhase/flux/issues/941)).
- On My map a selected thought offers Move to a space map and Copy link. Move asks for the space and its map (a space with no map gets one), keeps the thought's text, shape and size, takes along its connections to other thoughts that move with it, and has Undo. Copy link gives an address that opens My map with the thought selected ([#948](https://github.com/ColdPhase/flux/issues/948)).
- Flux's pages and its service worker now carry a real Content-Security-Policy. Scripts run only from Flux's own files and the hashed inline ones (never `unsafe-inline` or `unsafe-eval`), the page connects only to its own origin, and plugins, frames, `<base>` and forms to other sites are refused, so a script an attacker managed to inject could neither run nor send anything out; styles may still be inline. The offline page's button no longer uses an inline handler ([#979](https://github.com/ColdPhase/flux/issues/979)).
- The API writes a structured security event for each failed or limited sign-in, password reset or change, session or client revocation, consent decision, refused origin, refused request and encrypted-space lock or unlock, with no password, token, address or content in it; the events are listed in the monitoring guide ([#997](https://github.com/ColdPhase/flux/issues/997)).

### Changed

- The phone's "+" Create sheet is five list rows, Task, Thought, Decision, Page and Space, with the line "The same five on the computer (C)" and no Space picker of its own (the Create window has one), and a long press on a message opens one bottom sheet with the message at the top and its actions below, in the computer's order, in place of a lifted copy of the bubble with a small menu ([#1013](https://github.com/ColdPhase/flux/issues/1013)).
- Undo on an agent's message now takes back a page the agent started, by deleting it, while only that agent has written it and nothing names it; a page edited, linked or being typed in since stays, and the line says why. A Wiki page switcher that is already open drops a page deleted meanwhile ([#1021](https://github.com/ColdPhase/flux/issues/1021)).
- The panel that opens beside the work is headed by the label that opened it, on every device: "Space details" or "Message info" for a place's own panel, "Add to a Wiki page", "Connect your AI", "Propose a decision", "People and encryption" and "Linked objects" for the rest, and its close control says the same ("Close space details"). A proposed decision that replaces an earlier one says so once, in the sentence that names it, and a restricted space's details say who else can open it: the company's owners and admins ([#1058](https://github.com/ColdPhase/flux/issues/1058)).
- AI answers know who asks, where and when: every place (`/ai` in a space, a task's discussion, a direct message and its threads, an agent's private chat, a task an agent works on, a schedule's run) and both engines (an API key, or your own Claude Code or Codex) get one brief with your name, the time in your time zone, the place's name and each message's author and time; answers come in the language you asked in, as short plain text with `#12` and `[[Wiki page]]` that stay links after Show everyone; they may use general knowledge, say so when the conversation does not answer, and say when older messages were left out; an agent working a task is given its outcome and when it is done; the stiff "Fact, Interpretation or Proposal" labels are gone ([#1064](https://github.com/ColdPhase/flux/issues/1064)).
- An agent may open any public web page it needs, on an API key, on your own Claude Code and on your Codex alike: no list of allowed addresses and nothing to approve. It is told never to put anything from Flux into a web address, and Flux refuses an address that carries text the agent read in Flux. Agents on your own Codex now search the web too, and every answer still lists what the agent searched and the pages it opened ([#1065](https://github.com/ColdPhase/flux/issues/1065)).
- Agents search and read as much as a question needs: the limits of 5 searches and 20 addresses a run are gone, each search is charged as the provider reports it and the key's daily budget still stops spending, a run on your API key keeps a short note of each page it read and no longer sends the page's text again once it is noted, and an address nothing gave is still refused. A malicious page with many links could leak what an agent knows through which of its links the agent opens; the founder accepted that risk ([#1113](https://github.com/ColdPhase/flux/issues/1113)).
- An agent's page reads are no longer limited to 20 a minute (founder direction, 2026-11-09): a research run reads as many pages as its question needs, one after another; the server still reads at most 6 pages at once ([#1116](https://github.com/ColdPhase/flux/issues/1116)).
- An agent knows who wrote what: every message it reads, on your Claude Code or Codex and with an API key alike, names its author as you see them, "Asystent (Ada's agent)" for an agent (with the owner's full name when two people in the space share a first name) and "Ada Nowak · via Asystent" for an answer someone posted with Show everyone, which it never takes for its own; only people who can read the space are named, anyone else is "Former member". An agent gives a task to a person of the space by name, and sets or clears a task's due date like a person ([#1162](https://github.com/ColdPhase/flux/pull/1162), [#1163](https://github.com/ColdPhase/flux/issues/1163)).
- The README, the self-hosting and administration guides, the release installation guide, the security policy and the integration guide describe v0.2 (one company with spaces, simple AI with Connect AI and agents that have their owner's rights, local clients over MCP, encrypted spaces, the security work), v0.2 has release notes, and `./flux demo` says what the app says: a source, a Map with Thoughts and a Wiki page instead of "published material", "sketch" and "doc". `./flux export` names its argument a space. Screenshots that still show v0.1 (the README's, the People and invite pages, the New project page) are out of the pages until new ones are recorded ([#1172](https://github.com/ColdPhase/flux/issues/1172)).
- Flux v0.2 does not upgrade a v0.1 instance, because v0.1 had no users: `./flux upgrade` refuses a database that v0.1 wrote before it asks, takes a backup or stops anything, the migration step (`./flux up`, `docker compose up`, a release install) refuses it before any migration file runs with `FLUX_V01_DATABASE`, and `./flux restore` refuses a v0.1 backup with or without `--migrate`. The message says to install v0.2 fresh (a new folder, or `./flux reset`) and that there is no import of v0.1 data; the upgrade guide and the v0.2 release notes say so too. An instance interrupted during its first install, before anybody signed up, is not refused ([#1176](https://github.com/ColdPhase/flux/issues/1176)).
- The API's request log uses a request's `X-Request-ID` as its `reqId` when it is a short plain identifier (letters, digits, `.`, `_`, `:`, `-`, up to 64), so a proxy's id and the log line match; the performance report pairs server times with requests by that id, so every request has its time ([#827](https://github.com/ColdPhase/flux/issues/827)).
- A task an agent makes from a message keeps that message as its source, as a task made by a person does: the task opens the message in context and the message shows the task ([#844](https://github.com/ColdPhase/flux/issues/844)).
- Flux is lighter on a modest server. An open Map or Wiki no longer reads its access rules four times a second: it listens for changes and looks only on activity or every two seconds when idle, and a cursor that has not moved no longer wakes the other editors. The project, its people and its docs are not read twice at once, the app reads the person and the workspaces together and then the projects and messages together, the video-call code is not downloaded ahead of time, and a session read no longer signs a token nobody reads ([#850](https://github.com/ColdPhase/flux/issues/850)).
- The performance check measures what a 2 vCPU host feels: a CPU-limited phase that holds every request to a 50 ms p95, the first-screen download, idle database statements and restart times, and a browser test counts the API requests of each move between places ([#850](https://github.com/ColdPhase/flux/issues/850)).
- An idle server is quieter: its worker looks at its queues once a minute instead of every 30 seconds when nothing has woken it, and its other housekeeping looks less often too, so a Flux nobody is using makes about 95 database statements a minute, down from 122. A delayed or retried job can start up to a minute late instead of half a minute; a job sent now still starts at once ([#850](https://github.com/ColdPhase/flux/issues/850)).
- Settings › AI has one Connect AI: a Claude plan, a ChatGPT plan and API keys side by side, each with one usage line. Each agent picks its model from any connection, and nothing switches by itself ([#854](https://github.com/ColdPhase/flux/issues/854)).
- Flux sets no limits of its own on subscription runs: no runs a day, five-minute clock, step count, changes per run or background runs a day. A plan at its limit pauses the request with one line and resumes by itself; only technical safety bounds remain ([#843](https://github.com/ColdPhase/flux/issues/843)).
- An API key has one daily budget, for everything that runs on it. The per-run ceiling, the assistant's daily cap and the separate allowance for background suggestions are gone ([#854](https://github.com/ColdPhase/flux/issues/854)).
- An agent now has exactly its owner's rights, and it loses them the moment its owner does. Each agent has one "What it may do": Only read, Do it and tell me (the default) or Ask me first. Deleting and other people's things always wait for your OK, and only you, signed in, can give it ([#855](https://github.com/ColdPhase/flux/issues/855)).
- Undo now sits on the agent's message, next to one line that says what it changed, and the line is then struck through and ends "Undone by Ada". A deletion asks Delete or Keep, a task for someone else is a proposal with Approve, Edit and Skip plus Approve all, and the Inbox shows one item per agent run. Nothing that waits expires ([#855](https://github.com/ColdPhase/flux/issues/855)).
- MCP tool contract 2: the `flux://policy/{projectId}/{revision}` resource and bootstrap's `trusted.approvedPolicy` are gone, because an agent now has its owner's rights. A local client set to Only read gets `AGENT_ONLY_READS`; its other changes wait like the assistant's ([#855](https://github.com/ColdPhase/flux/issues/855)).
- A local Claude Code or Codex now acts with your rights, like your agents, and has the same "What it may do": Only read, Do it and tell me, or Ask me first. Deleting and other people's things always wait for your OK, and so does everything under Ask me first; you approve in the Inbox, one item per client with Approve all. A unit or request a client gives to someone else's client waits too. Disconnecting a client closes what it had waiting. Only you, signed in, can approve: the client's own token cannot ([#859](https://github.com/ColdPhase/flux/issues/859), [#855](https://github.com/ColdPhase/flux/issues/855)).
- Signing in Claude Code, Codex or another local client is one click: its sign-in opens one page that says who asks and where access goes, and **Allow** is the whole setup. Allow makes the client's agent (yours) and its connection at "Do it and tell me", or finds the one the client already has; **Deny** and merely looking at the page make nothing. The client then acts with your rights, in the spaces where AI is on, and no more ([#859](https://github.com/ColdPhase/flux/issues/859)).
- Disconnect ends a client's access at once and closes what it had waiting; signing in again makes a new connection and gives the client's earlier agent back ([#859](https://github.com/ColdPhase/flux/issues/859)).
- A client's undo of a task it made waits for your OK like any deletion, and an Approve that comes after the claim or session it was made under has ended says so in plain words instead of applying ([#859](https://github.com/ColdPhase/flux/issues/859)).
- The agent runtime has no fixed number of people: one runtime serves everyone with Connect AI, each person under their own user id. How many agents run at once follows from memory, about 2 on 4 GB, and the others wait with "Waiting for room on the server". `FLUX_RUNTIME_MAX_RUNS` changes the number ([#860](https://github.com/ColdPhase/flux/issues/860)).
- A host that does not meet a runtime requirement, such as `kernel.yama.ptrace_scope=0`, stops the runtime with one clear message and the fix. There is no restart loop, and `./flux up` fails instead of reporting a healthy Flux ([#860](https://github.com/ColdPhase/flux/issues/860)).
- Moving between places asks the server less: the project, its people, the members, the space's docs and the agents' unread dots are kept for a moment, and what waits for you is read once per page, so the next view shows them without asking again. Anything that could change them (a change you make, a live update, signing out) forgets them, and a refresh on focus still reads. Going from Home to the Inbox now costs two requests instead of four, and entering a space 15 instead of 20 ([#862](https://github.com/ColdPhase/flux/issues/862)).
- An open tab no longer asks the server on a timer while its live connection is up: a space's conversation, Tasks, a thread and the working agents read when something changes, so a tab nobody touches makes almost no requests (a space's conversation made 70 a minute; the Inbox count still checks every two minutes, as some of its changes send no event). "Seen by" in a space appears when someone sees your message and stops naming someone who can no longer read the space, a live update tells only the change it carries what to read again, a tab back from sleep or a network change reconnects, and opening a page's live editing keeps what the space had read ([#862](https://github.com/ColdPhase/flux/issues/862)).
- The Inbox is the one list of what needs you, and Home shows its top three under "Waiting for you" with the same count: every decision is one row ("2 decisions waiting"), each row opens the Inbox on its item, and nothing on Home acts. Home keeps only that and "Continue where you left off"; on the phone "My tasks (N)" and "My map" are rows under the waiting items ([#865](https://github.com/ColdPhase/flux/issues/865)).
- "Mine" and My tasks include the tasks your own agents own ([#865](https://github.com/ColdPhase/flux/issues/865)).
- An idea is a Thought and a canvas is a Map, in every label, in search and in Create. The Sketchbook is now **My map**, your one private map at `/map`; "Your notes" are thoughts on it, and Create's Thought puts a thought there. "Sketch" is "Map" (the default title is "Untitled map"), and the toolbar is "Map tools" ([#866](https://github.com/ColdPhase/flux/issues/866)).
- A message shows Reply in thread, Create task and ⋯. The ⋯ menu is one level, in the same order on every device: Add to map, Copy link (a phone's long-press list starts with Reply in thread and Create task). Cite, Record a result, Details, Propose a decision, Hand off to an agent, Copy text and Done / Not now are gone from messages; a private message can be added to My map, also in a 1:1 the other person left, and a direct-message reply's Copy link opens its thread at the reply ([#867](https://github.com/ColdPhase/flux/issues/867), [#948](https://github.com/ColdPhase/flux/issues/948)).
- Create offers the same five types on the phone and the computer, Task, Thought, Decision, Page (a Wiki page) and Space, in place of Message, Project, File or link and Map; Decision on the phone opens the same window as the computer's, and a Page is made from it. The phone's sheet no longer hands a picked file to the composer ([#867](https://github.com/ColdPhase/flux/issues/867)).
- A task has one discussion: an agent writes in it like anyone (`flux_discuss_task`, read with `flux_get_task_discussion`), the separate "Agents' thread" is gone, and the space's conversation shows one line for each task event instead of the discussion's first message and thread. Agents may write five messages in a row in it until a person writes, by any tool; a line Flux writes for an agent at work on the task (its report, a question to another agent, the answer, "Stopped by …") is always posted ([#868](https://github.com/ColdPhase/flux/issues/868)).
- Tasks: "Not pursued" is Done with a "dropped" note ("Done · dropped"). A done task has one optional line, "What came of it", also written in its discussion, and a "Dropped, not finished" check; the "Result" button and the "Record a result" form are gone from the task panel. A blocked task waits for one person, one decision or one other task and goes back to Doing by itself when that is resolved: the person says "Done" in the Inbox or the panel, the decision is accepted, or the task is done. The stream says "#4 can continue: the decision was accepted" and the owner is told once; an agent picks the task up again ([#868](https://github.com/ColdPhase/flux/issues/868)).
- An agent's task that is Blocked when its run ends stays Blocked with the agent (it was marked Done, or handed back); a task something waits for cannot have its creation undone, and the tasks that wait for a decision or a task are not stuck when the waiting task's creation is undone ([#868](https://github.com/ColdPhase/flux/issues/868)).
- Tasks: a task is To do, Doing, Blocked or Done, and the board has those four columns; a dropped task is Done with a "dropped" note. Board and List share one control row (Board | List, Mine, Search) on every device, the phone included, and a narrow board scrolls its columns sideways. A card shows its title, number, due day and owner, and a blocked card one "Waiting for" line ([#868](https://github.com/ColdPhase/flux/issues/868)).
- The task panel hides empty rows and texts and has no ⋯ that held only Copy link; giving a task to one of your agents is its Owner field. It appears once its relationships are read, so nothing moves after it opens ([#899](https://github.com/ColdPhase/flux/issues/899)). A thread's panel leaves with its content ([#901](https://github.com/ColdPhase/flux/issues/901)), a thread opens at half height on the phone, and Tasks loads as its board's shape ([#902](https://github.com/ColdPhase/flux/issues/902)).
- The Wiki is two columns, the sidebar and the page: the page is edited where it is read, and versions save by themselves while you write and when you leave. The title is the page switcher (Find a page, + New page), ≡ lists the page's headings, and ⋯ holds History (compare and Restore), Copy link, Export, Import a Markdown file and Rename page. A task opened from a page opens over it ([#869](https://github.com/ColdPhase/flux/issues/869)).
- Search is one tool: ⌘K, the sidebar's Search and the phone's Search open the same dialog, with the results in groups by kind and a plain sentence for a hint. The Search page, its filter chips, the place filter and the "See all results" row are gone, and so are the Create rows and the `@` and `#` scopes ([#870](https://github.com/ColdPhase/flux/issues/870)).
- A decision is called "Decision" everywhere: the Inbox card, the return summary and the notification no longer say "rule" or "proposal". "Replaces" and "In the Wiki" are plain sentences, drawn only when they apply: "This replaces the decision … (12 Oct).", "This was replaced by the decision …" and "Shown on the Wiki page …". Accepting a decision that replaces another only marks the old one replaced ([#871](https://github.com/ColdPhase/flux/issues/871)).
- Words about who can see a place appear only when the audience differs from the place's default. A space's conversation, its threads, a task, a space's map and a direct message say nothing under the box; a private map still says "Only you", and a private answer still says who sees it. Header subtitles that described a page are gone, "Who can see this" in the header's ⋯ menu is "People", and "Came from" on a task is "From" ([#871](https://github.com/ColdPhase/flux/issues/871)).
- A place's panel has one name on every device: "Space details" in a space and "Message info" in a direct message. Home, My map and My tasks have no Details ([#871](https://github.com/ColdPhase/flux/issues/871)).
- An encrypted space's people and keys moved from Home → Details → People to the space's own settings ("People and encryption"). Removing someone from the company now also ends their place in its encrypted spaces, and the only admin of an encrypted space makes another admin before leaving ([#874](https://github.com/ColdPhase/flux/issues/874)).
- One Flux is one company (F-037): the first account sets the company up, as its owner, with the default space Everyone that holds the whole company. With single sign-on everyone the identity provider lets in joins on their first sign-in; without it, company admins invite people with links. Projects are now called spaces, in one flat list in the sidebar (Home, Inbox, My tasks, My map, Spaces, Messages); a person sees only the spaces they were added to, everyone but a guest starts spaces, and a space's creator is its first admin. Settings › Company replaces People, with the company's name and its people. There is no way to create or switch workspaces. ### Security

- Production dependencies no longer carry a known HIGH or CRITICAL advisory: Better Auth 1.7.18, Fastify 5.12.8, `@fastify/static` 10, the MCP SDK 2.4 (one MCP request is limited to 1 MiB and 10,000 argument elements), `markdown-it`, `zod`, `pg-boss` 12.38 and the other pinned packages are current ([#877](https://github.com/ColdPhase/flux/issues/877)).
- A password reset, a password change that signs out the other devices, and "Sign out all other devices" now disconnect the person's local AI clients: their connections, runtime sessions and OAuth tokens end, so a client connected from a borrowed session no longer outlives the owner's recovery. Each client connects again with one click on the consent page, and gets the same agent back. Better Auth's own `/revoke-sessions` and `/revoke-other-sessions` endpoints are off ([#989](https://github.com/ColdPhase/flux/issues/989)).
- Passwords need 12 to 128 characters, and a common or easy-to-guess password, or one built from the person's name or email, is refused; the list ships with the server and nothing is sent anywhere. Sign-in limits are kept in PostgreSQL, so every API process counts together, and each account backs off after five wrong passwords (30 seconds, up to 15 minutes), whatever the client address, without keeping out a browser that has signed in to it before (a signed `flux.device` cookie), and the answer gives no exact wait; a reset clears it. Migration 0026 ([#990](https://github.com/ColdPhase/flux/issues/990)).
- An unexpected server error now answers `500` with a code only in every space, and logs only its class and code: its message (a SQL or file-path text, or text it quotes from the request) no longer reaches the browser or the log. Fastify's own 4xx answers keep their messages ([#991](https://github.com/ColdPhase/flux/issues/991)).
- Every response carries `X-Content-Type-Options: nosniff` and `Referrer-Policy: same-origin`, `/api/` answers carry `Cache-Control: no-store`, and an https public origin makes the API send `Strict-Transport-Security: max-age=31536000`. The reverse-proxy guide says to pass it on ([#992](https://github.com/ColdPhase/flux/issues/992)).
- `FLUX_SESSION_IDLE` (default 7 days) and the new `FLUX_SESSION_MAX_AGE` (default 30 days from sign-in, however much the session is used) set how long a session lasts; `verified` sign-up answers an address that has an account like a new one and mails its owner instead ([#993](https://github.com/ColdPhase/flux/issues/993)).
- The install guides create the owner account while the server is still on its loopback address, before it is public, and `./flux up` and the API log warn while nobody has signed up on a public address, because the first account becomes the company's owner ([#994](https://github.com/ColdPhase/flux/issues/994)).
