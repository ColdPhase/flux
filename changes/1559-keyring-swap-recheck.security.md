- The keyring checks again, every minute and before every request, that its memory cannot be written to disk. A running container's swap limit does not stay: `systemctl daemon-reload` (run by package upgrades and configuration tools) resets it, and the keyring only checked at start. When swap has become possible it now wipes its boot key, logs one line with the fix, answers 503 and turns its health check red; API and worker lock every encrypted space with the reason, and `./flux up` prints the line. Restarting Flux (`./flux down`, then `./flux up`) sets every container's limit again and the admins unlock their spaces again ([#1559](https://github.com/ColdPhase/flux/issues/1559)).
